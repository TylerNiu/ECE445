# Digital lab notebook

This directory is the team's chronological record of project work. Each entry should be committed to Git so the repository history records when the work was documented.

## Entry requirements

Every entry should include:

- date and contributors;
- objective or question being investigated;
- work performed, including enough detail to reproduce it;
- equipment, software, part numbers, and relevant settings;
- measurements, observations, calculations, or links to raw data;
- decisions and their rationale;
- problems, risks, and deviations from the plan;
- next steps and responsible person.

Use `entries/TEMPLATE.md` for normal work sessions. Use `meetings/TEMPLATE.md` for TA, sponsor, or team meetings.

## File naming

Use ISO dates so files sort chronologically:

`YYYY-MM-DD-short-description.md`

For multiple entries on one day, append a distinguishing suffix, such as `YYYY-MM-DD-power-test-01.md`.

## Linking evidence

Keep raw files in the appropriate project directory and link them from the notebook entry. For example:

`[Power test data](../../testing/results/2026-09-15-power-test.csv)`

Images and scans belong in `media/` or the relevant project directory. Avoid putting large generated binaries in the notebook entry itself.
